## 文件与调用方式

- `node.py` 保留唯一对外节点 check、retouch；`__init__.py` 导出不变。
- `real.py` 组织真实流程，使用资产库 load_image。每轮最多读取配置的 candidates_per_round 张候选，使用 photo_urls[0] 作为主合照，额外照片暂不读取。
- `vision.py` 使用内嵌图片内容发送原图和候选，检查身材、手部、人数、文字、需求一致性及可判断性。内部 findings 字段不会写入 WeddingState；缺陷全部转为既有 issues。
- `model_calls.py` 统一 get_llm、with_structured_output。输出格式错误最多重试一次；网络或超时错误不增加应用层重试。超时沿用 settings.llm_timeout_seconds，每次 invoke 的 SDK 请求预算为 max_retries + 1，最多两次 invoke 的总预算不能超过 settings.max_agent_steps；预算不足时不执行第二次。本模块不改公共入口。
- `face_compare.py` 提供内部 compare_faces 图片入口及 compare_with_extractor 测试入口；无任务级全局缓存。向量匹配保持原图 A/B 顺序，允许候选换位，返回截断到 [0,1] 的余弦相似度。必须使用同一模型、同一维度，恰好两个主体，阈值按该模型实测标定。
- `prompts/vision.md`、`prompts/retouch.md` 是可编辑模型提示词。

视觉一次处理全轮候选；不能可靠观察的图在 issues 中注明并拦截。真实 total 暂沿用 fake 的两个身份分数均值，仅用于在合格候选间排序，不声称为综合画质评分。若要改变排序政策，先统一产品评测方案。

返工 agent 必须输出当前契约。target=none 仅允许无用户反馈且选中当前合格候选；其他 target 不得同时填 image_id；用户明确选择 face/hands/body/style/other 时，方案须符合对应返工方向。AI 方向偏差由代码纠正，保留修改说明；空说明使用默认说明，非法候选编号使用规则选图，模型调用失败使用 fake 共用的规则方案。不完整评分等输入错误仍抛 ModuleError。

## 人脸服务选型后要补什么

1. 确定获准服务、模型版本、照片处理规则、双人主体提取方式和分数尺度。
2. 确定原图 A/B 对应；若检测数量不是两位，不擅自根据性别或位置挑人。
3. 在本目录实现 compare_faces；本地方案可使用 compare_with_extractor，云服务按实际 API 返回独立分数。
4. 外部调用超时、重试、费用上限和新增依赖／配置由框架同学统一配置。本次未增加任何依赖或公共配置，也没有自行安装人脸模型或发送照片。
5. 用授权样本标定 FACE_SIM_THRESHOLD，再做独立真实验收。原图模糊、无脸、多脸，以及候选提取失败的处理需与框架统一；当前适配层明确报错，尚未提供逐候选容错策略。

真实视觉和返工使用已有 LLM_API_KEY、LLM_MODEL_VISION、LLM_MODEL_AGENT、LLM_BASE_URL 等配置。开启前确认服务获准处理这些照片。代码不会向模型发送 brief.invitation 的姓名、日期、地点等交付资料；任务、图片内容和原始错误不写日志。错误消息使用用户可读中文。

## 离线人工与模型结果对照

```bash
uv run python -m app.modules.review.evaluation /私有目录/annotations.json /私有目录/predictions.json
```

annotations.json 是人工标注模板填好后的**列表**。身份标签使用“像本人”“不像本人”“无法判断”；review.status 使用 pending（未复核）、reviewed（已复核）、adjudicated（分歧已裁定）。human_passed 只能为 true、false 或 null；仅已复核／裁定且非 null 的标签计入指标。

模板的 expected_round_target 是整轮人工裁定的返工方向，null 表示未裁定；候选内 expected_target 用于人工逐图讨论，不能把同一个整轮返工决策重复算四遍。

predictions.json 是离线报告列表，每项示例：

```json
[
  {
    "sample_id": "sample_001",
    "result": {
      "scores": [{"image_id": "img_1", "face_sim": [0.9, 0.88], "body_ok": true, "hands_ok": true, "issues": [], "total": 0.89}],
      "best_image_id": "img_1",
      "passed": true
    },
    "retouch_plan": {"target": "none", "patch": "选择已合格候选", "image_id": "img_1"}
  }
]
```

sample_id、result 包装是离线报告格式，不新增工单字段。图片以 sample_id + image_id 对齐。工具依据 scores 和当前 FACE_SIM_THRESHOLD 重新判定单图是否通过，不以整轮 passed 代替每张图结果；重新计算后的阈值应在报告运行记录中登记。

输出包含 tp/tn/fp/fn（正类为“合格”）、有效图片数、未复核／无法判断数、缺预测数，以及误放行率、误拦截率和整轮路由一致率的分子、分母、比率。没有分母时为 null。缺模型预测不会伪装成“系统拒绝”。现已补充按缺陷类别的漏检率、推荐质量、耗时与调用数摘要和版本元数据，另提供阈值扫描与人物隔离检查；工具命令见下文；合成指标不能代表真人照片效果。

空模板、真实照片、原始授权与真实报告不用于本次提交。`batch_eval.py` 仍是 fake 示例工单批量工具，不能接收人工标注模板。

## 人工评测与样本准备

状态：供收集样本、人工标注和真实服务选型使用的工作稿。真实模型分支已编码，照片到人脸特征的服务仍未接入，本文没有真实效果数据。业务接口仍以现有模块契约为准；标注模板中的字段仅用于离线评测，不新增工单字段。

### 1. 本轮评测对象

当前产品输入是一张双人合照，每轮生成 4 张候选。评测应同时查看原始合照、已确认的需求单 brief 和候选图。

- 单张图：判断两个人的身份、身材、手部、人数、文字及需求一致性。
- 一轮候选：是否至少有一张合格；推荐的图是否合格。
- 返工：针对具体问题是否退回正确模块；重做后问题是否解决。

单人照片、两人各一张、多张照片的人物对应暂不作为当前已支持场景。缺失或不符合输入范围时记录待协调问题，不自行扩展接口。

### 2. 人物对应与人工判断

先由人工在原图确定 person_a、person_b，并在标注中注明位置，例如“原图左侧人物”“原图右侧人物”。这些编号不代表性别、身高顺序或新娘／新郎。候选图中即使两人换位，也要按身份对应；不能直接按候选图左右顺序比较。

两位标注人分别对照图片和需求独立标注；有分歧时讨论并记录最终裁定。无法确认身份、手被遮挡、全身比例看不清等情况填“无法判断”，说明原因，不猜测。第一轮可先由一人标注，第二人复核；在没有复核前，结果标为待复核。

人工身份判断填写“像本人／不像本人／无法判断”，不凭感觉填 face_sim 浮点数。真实服务接入后再记录该服务给出的两个分数；不同服务分数不能直接横向比较。

### 3. 单张图判定规则

|检查维度|人工检查内容|不合格示例|当前结果字段／返工方向|
|---|---|---|---|
|人物 A 身份|对照原图五官与可识别特征，避免只判断“好看”|变成另一张脸、两人脸混合|face_sim[0]；generate|
|人物 B 身份|单独对照，不能用两人平均分代替|一位很像，另一位明显不像|face_sim[1]；generate|
|身材与比例|结合原图、heights_cm、body_types，检查身高差、体型与肢体比例|无授权瘦身、改变身高关系、肢体异常拉长|body_ok、issues；shot|
|手部|检查可见手指、手掌、关节和互动处的结构|多指、融合、断裂、抓握关系明显异常|hands_ok、issues；generate|
|主体人数|两位应完整出现；区分主角和需求中明确允许的背景人物|主角缺失、复制出第三位主体、无要求的明显人物|issues；generate|
|文字|检查模型生成的可见文字，不把本阶段没有请柬文案当缺陷|乱码、破碎字、无要求的文字|issues；当前 fake 规则退回 prompt|
|造型与风格|对照 brief 中已确认的妆容、服饰、风格和 keep_features|婚纱或妆造不符、眼镜等指定特征消失|issues；造型问题退回 look，身份问题退回 generate|
|场景与拍摄要求|对照 brief 的背景、姿势、表情等已确认需求|要求保留场景却换背景、姿势不符|issues；镜头问题退回 shot，指令矛盾退回 prompt|

造型、背景、表情的合理变化应按用户需求判断。beautify 默认 none；不能因为修图后更符合审美就允许改变本人五官、体型或指定特征。light 也不等于允许换脸。

真实视觉检测如何把这些问题映射到 issues、是否所有问题都必须拦截，需要与框架和产品负责人统一。当前 fake 实现将非空 issues 全部作为拦截条件，不能把它称为已验证的真实检测政策。

### 4. 合格、选图与返工

当前程序的合格条件：两个人脸分数分别达到 settings.face_sim_threshold、body_ok=true、hands_ok=true、issues 为空。当前默认阈值为 0.5，只是骨架配置，未经真实样本标定；不是所有服务通用的及格线。

- 一轮至少一张合格：check.passed=true，在合格图中选最高 total 的 best_image_id。
- 四张全部不合格：check.passed=false，best_image_id=null，retouch 制定返工方案。
- **一张不像但其他图合格，不应让整轮失败。** “放一张不像的图”的单图验收可只评测该图；整轮失败测试要确保四张都不合格。
- 无用户反馈且已有合格候选：retouch 可返回 target=none 和该候选 image_id；不能引用历史轮次的图片。
- 用户明确要求重做：本轮 fake 实现优先按 reason 和 note 处理，不能用旧评分忽略用户意见。
- 同一张有多个问题：记录全部问题。当前 fake 先处理脸／手部，再身材，再造型，再指令；真实模式也由代码按同样优先级确定方向，AI 只负责说明。
- 返工次数、任务失败和重新生成流程由框架管理，review 不自行增加 retry_count。

返工 target 的人工预期只使用已有的 generate、shot、look、prompt、none。场景存在歧义时先填写“待裁定”，不为测试编造业务取值。

### 5. 首批样本清单

建议先收集 **10 组本人授权的双人合照，各配 4 张候选，共 40 张**，用于发现问题与搭建评测流程。该数量是起步计划，不是统计有效性结论。没有真实生成图时，先登记需求和授权状态，候选栏留空；不要用 fake 分数冒充真实样本。

|编号|希望覆盖的条件|原图要求／候选检查重点|
|---|---|---|
|S01|基础正常样本|双人清晰正脸，正常光线；至少一张人工判定合格候选|
|S02|只有 A 不像|B 保持身份；验证不能用平均分放行|
|S03|只有 B 不像|A 保持身份；验证双人独立判断|
|S04|身份混合或人物换位|换位本身不是错误；验证人物对应，识别身份混合|
|S05|身高差不超过 5 cm|参考明确身高信息，检查相近身高是否被改变|
|S06|身高差大于 5、且不超过 15 cm|检查比例和不同姿势下的身高关系|
|S07|身高差超过 15 cm|检查较大身高差是否保留|
|S08|保留特征与自然体型|本人同意用于测试的眼镜等特征；beautify=none|
|S09|手部互动|牵手、拥抱等可见互动；检查手指、手掌融合|
|S10|风格、人数与文字问题|覆盖造型不符、多余主体和乱码；可通过同组不同候选覆盖|

以上条件可以复用同一组照片，但不能用同一组反复生成代替人物多样性。某类缺陷未出现时标记“待补样”，不把正常图硬标成缺陷。额外补充边界样本：手部遮挡、局部身材不可见、低清晰度／遮挡原图；后两者主要验证输入筛查与模块交接，不计为正常条件下的人脸检测效果。

还需覆盖这些流程场景：四张都不合格、一张合格其余不合格、最高总分图不合格、同分排序、用户 face/body/hands/style/other 五种重做原因、空候选、重复编号、历史评分、返工次数耗尽。程序层面已有对应部分测试；真实图片层面仍需收集。

### 6. 每组样本的登记与标注步骤

1. 登记匿名 sample_id、授权凭据编号及允许用途。确认原图中两位都已授权；当前不放入真实个人资料。
2. 原图和候选图通过资产库保存，用资产编号在私有登记中关联。不要把照片、含访问凭据的 URL 或授权原件提交到 Git。
3. 登记 brief 的必要内容、生成服务版本、种子、生成时间；原图人物对应由人工确认。
4. 每张候选单独复制一条标注模板，填人脸身份、身材、手部、人数、文字、需求一致性与问题说明。
5. 标记 human_passed、expected_target；无法判断时保持 null，写明原因，交复核者处理。
6. 接入真实检测后，把模型输出与人工最终标签对照；模型分数不覆盖人工标签。

使用同目录的 `sample_annotation_template.json`。它是空白模板，所有标签初始为空；填完的真实登记与报告留在获准的私有位置，不提交本模块目录。当前 batch_eval 接受现有工单 JSON，**不能直接把人工标注模板传入 batch_eval**。

### 7. 选型与阈值标定

按人物／情侣组划分数据，避免同一人进入标定集和验收集。首批可暂分 6 组标定、4 组保留验收；人数过少时只记录具体失败案例，不给出稳定准确率承诺。调阈值或修改规则后，验收集必须保持独立；若已反复用于调参，另收集新验收样本。

记录以下指标及原始计数，人工“无法判断”单独统计并排除出分母：

|指标|计算方法|说明|
|---|---|---|
|误放行率|人工不合格、系统却通过的图数 ÷ 人工不合格图数|两人任一身份失败也计入不合格|
|误拦截率|人工合格、系统却拒绝的图数 ÷ 人工合格图数|检查阈值是否过严|
|缺陷漏检率|某类缺陷存在却未报告的图数 ÷ 该类缺陷图数|人脸、手部、身材、人数、乱码分别统计|
|返工路由一致率|与人工裁定 target 一致的案例数 ÷ 已裁定返工案例数|未裁定案例另列|
|候选轮通过率|至少有一张人工合格图的轮数 ÷ 已完整标注轮数|反映生成质量；不能单归因于 review|
|推荐图合格率|推荐图人工合格的轮数 ÷ 有推荐图且已标注的轮数|同时报告推荐为空的轮数|
|耗时和调用次数|每轮 check、retouch 耗时和请求次数|质检 1 分钟是演示目标，尚未实测|

分母为 0 时写“无样本”，不要写 0% 或 100%。真实 total 的计算方法、分数尺度、人脸阈值和服务预算都待选型后统一；本轮 fake 的 total 是两个示例人脸分数的均值，不代表综合画质分。

### 8. 当前验收与下一步

已完成：review 模块测试 212 项、契约测试 24 项、全量测试 282 项通过；示例评分与返工报告可复现。包含 fake 与真实分支测试替身集成、双人向量配对、离线指标、阈值扫描、独立诊断、并发隔离和基线对比验证；这些测试不能证明真实照片效果。

真实验收前需完成：授权样本收集与复核、双人对应规则、真实人脸及视觉服务接入、阈值标定、独立验收集评测。建议起步验收逐例检查：A/B 任一明显不像不能放行，手部／比例／人数／乱码样本正确报告，至少一张合格时正确推荐，所有已裁定返工样本路由一致。未覆盖的类别列为未验收。百分比验收目标由负责人在看到样本规模与基线后确认。

## 现有工具运行方式

在 `wedding-agent/` 执行。以下示例使用合成数据或 mock。

```bash
uv run python -m app.modules.review.evaluation app/modules/review/examples/synthetic_annotations.json app/modules/review/examples/synthetic_predictions.json
uv run python -m app.modules.review.calibration --help
uv run python -m app.modules.review.regression --help
uv run python -m app.modules.review.diagnostics app/modules/review/examples/diagnostic_entry.json --mode mock --stage check
uv run python -m app.modules.review.diagnostics app/modules/review/examples/diagnostic_entry.json --mode mock --stage vision --image-id img_2
uv run python -m app.modules.review.live_batch app/modules/review/examples/batch_manifest.json --mode mock
```

标定和回归参数以工具 `--help` 为准。标定集与验收集按人物隔离，记录模型、分数尺度、提示词与数据集版本；标定不会修改公共阈值配置。版本对比需保证样本覆盖一致。

诊断输入为 `{sample_id, state, consent}`，批量输入为 `{dataset_version, samples}`，仅供离线工具使用。示例资产地址是占位地址，授权默认 false，不能直接切 live。返工诊断需要完整当前评分，不支持截取单张评分。

live 必须显式选择，review 已配置为真实模式，双方已授权且登记凭据引用，获准服务与当前配置一致，相关模型配置可用。check／face 还需人脸服务接入，目前尚不可用；视觉／返工仅使用模型替身验证。

`--output` 写入新的 JSON 文件，权限为 0600，不覆盖旧文件。真实报告留在获准私有位置，不提交 Git。批量 succeeded 表示执行完成，不表示照片合格；失败记录不能冒充完整预测。评测前取出批量报告 predictions 列表并核对错误与覆盖。

调用统计区分模拟与真实调用。request_budget_upper_bound 是模型请求预算上界，不代表实际收费次数，也不包含尚未确定的人脸 SDK 重试。报告不含图片、资产 URL、密钥或原始工单，但评分与返工说明仍应私有保存。
