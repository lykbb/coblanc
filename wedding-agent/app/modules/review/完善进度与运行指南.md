# review 第 1–5 步完善进度

所有新增文件在 app/modules/review/，分支 module/review。未新增依赖、公共配置或工单字段。尚未提交／推送。

## 1. 评测指标：已编码并验证

evaluation 输出：误放行、误拦截，身份／身材／手部／主体人数／文字／需求一致性各类缺陷漏检率，推荐图合格率，缺失预测与缺失整轮返工方案数，耗时／调用数摘要及允许的版本信息。

各维度使用人工对应标签，只统计已复核或裁定样本；未知标签不当作正确结果。身份同时报告单图任一不像，以及人物 A／B 分别的漏检率。主体人数、文字和需求问题依据统一中文 issues 识别，旧数据的不同措辞可能无法匹配，后续真实数据应采用 vision.finding_issues 的规范说明。

只有已标注的推荐图才计入推荐质量分母；无推荐的轮数单独统计。没有分母时 rate=null。缺失计数必须与比率一起阅读，不能把覆盖不完整的高比例当作验收通过。

模型／提示词／数据集版本由离线报告 metadata 提供，没有版本记录就无法可靠追踪基线；多个版本会标记 mixed_run_metadata。报告只保留允许的元数据键，不输出照片或密钥。

## 2. 独立联调：mock 跑通，live 入口已准备

```bash
uv run python -m app.modules.review.smoke --mode mock
uv run python -m app.modules.review.smoke --mode mock --stage vision
uv run python -m app.modules.review.smoke --mode mock --stage retouch
```

程序在内存生成几何双人示意图。mock 不访问模型、不写照片文件；报告明确 model_invocations=0、simulated_invocations=2。

已有模型配置并确认服务及费用后，可显式选择 `--mode live`，单独检查视觉／返工结构化输出，无需启动整条生图链。本轮没有执行 live。几何图仅检查模型请求能否工作，不能证明真人视觉效果。check_seconds 在这个独立诊断里是视觉阶段耗时，不包含尚未接入的人脸服务。

CallStats 是调用者持有的临时记录，不进入 WeddingState，不在模块全局保存。model_invocations 表示应用层调用数；request_budget_upper_bound 是 SDK 最大请求预算，**不是实际收费请求数**。SDK 实际重试次数需供应商侧观测。节点默认不输出额外遥测字段。

## 3. 人脸适配层：算法与接口完成，供应商仍待接入

compare_batch_with_extractor 提取原图一次，批量匹配候选人物。每次传递剩余 timeout_seconds，并检查整轮截止时间、候选编号、数量和提取调用预算。供应商适配器必须真的遵守传入超时；本模块不会声称可以强制中断任意不遵守协议的提取器。

完整 check 的 compare_faces 仍明确报“服务尚未接入”。还需要负责人确定模型／服务、获准照片处理方式、主体提取规则、新增依赖与配置。当前不自行安装或选择人脸服务。

## 4. 回归集与阈值工具：合成基线可复现，真实集待收集

空白标注模板新增匿名 person_group_id、两位 person_ids 和 split。split 使用 calibration 或 validation；两组数据中同一人物或情侣组重复会阻止标定，不能只按图片文件名随机划分。

```bash
uv run python -m app.modules.review.evaluation app/modules/review/examples/synthetic_annotations.json app/modules/review/examples/synthetic_predictions.json
uv run python -m app.modules.review.calibration app/modules/review/examples/synthetic_annotations.json app/modules/review/examples/synthetic_predictions.json --thresholds 0.5 0.7 0.9
```

示例完全是程序构造的标签与分数，共 3 组、12 张候选登记，没有真人照片、真实人工验收或模型质量数据。默认骨架阈值为 0.5 时可复现：扫描在标定集选择 0.7，但独立验收集出现 4/4 误拦截，展示为什么不能只看标定集。**0.7 不是项目真实阈值建议**。

工具先降低误放行，再降低误拦截；同等表现选择最接近现配置的阈值。只用 calibration 集选阈值，再报告 validation 集效果。缺少合格／不合格样本或完整预测时不推荐阈值。报告不自动修改 settings／.env。显式扫描会移除旧阈值生成的固定身份不足说明，再重新应用身份门槛；其他视觉缺陷继续拦截。

真实数据需本人授权、人工复核、记录同一模型版本与分数尺度。阈值工具只是算法验证，尚未完成真实阈值标定。

## 5. 失败处理与完整流程：保持现有政策并补齐测试

原有 7 项 fake 六接口流程案例继续通过，新增 3 项真实 review 分支集成测试：测试替身驱动的视觉失败→agent 返工→再次质检→交付；视觉漏返一张候选→整轮失败；agent 指定历史候选→停止交付。

这些测试使用真实模块代码与接口，模型及人脸服务仍是测试替身。没有重新提问，不丢原始照片／回答，不越过框架重试上限，最终交付用户选择的图片。

单张无法评测目前保持既有的**整轮失败**行为，不自行改为“剩余三张继续”。部分继续、补试单张、失败提示和计费政策需要框架同学统一；本轮只测试现有行为。真实模型调用超时／非法输出转换为约定 ModuleError，不在错误消息中泄露图片或供应商原始内容。
