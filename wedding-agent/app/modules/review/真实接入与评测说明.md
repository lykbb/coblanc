## 文件与调用方式

- `node.py` 保留唯一对外节点 check、retouch；`__init__.py` 导出不变。
- `real.py` 组织真实流程，使用资产库 load_image。每轮最多读取配置的 candidates_per_round 张候选，当前只支持一张双人原图。
- `vision.py` 使用内嵌图片内容发送原图和候选，检查身材、手部、人数、文字、需求一致性及可判断性。内部 findings 字段不会写入 WeddingState；缺陷全部转为既有 issues。
- `model_calls.py` 统一 get_llm、with_structured_output。每个节点仅一次应用层 invoke，无循环重试；超时沿用 settings.llm_timeout_seconds。公共 get_llm 的 SDK 重试为 1，因此请求预算至多 2 次；若它加初次请求超过 settings.max_agent_steps，调用前报错。本模块不改公共入口。
- `face_compare.py` 提供内部 compare_faces 图片入口及 compare_with_extractor 测试入口；无任务级全局缓存。向量匹配保持原图 A/B 顺序，允许候选换位，返回截断到 [0,1] 的余弦相似度。必须使用同一模型、同一维度，恰好两个主体，阈值按该模型实测标定。
- `prompts/vision.md`、`prompts/retouch.md` 是可编辑模型提示词。

视觉一次处理全轮候选；不能可靠观察的图在 issues 中注明并拦截。真实 total 暂沿用 fake 的两个身份分数均值，仅用于在合格候选间排序，不声称为综合画质评分。若要改变排序政策，先统一产品评测方案。

返工 agent 必须输出当前契约。target=none 仅允许无用户反馈且选中当前合格候选；其他 target 不得同时填 image_id；用户明确选择 face/hands/body/style/other 时，方案须符合对应返工方向。空说明、不完整评分、历史候选和模型格式错误都抛约定的 ModuleError。

## 人脸服务选型后要补什么

1. 确定获准服务、模型版本、照片处理规则、双人主体提取方式和分数尺度。
2. 确定原图 A/B 对应；若检测数量不是两位，不擅自根据性别或位置挑人。
3. 在本目录实现 compare_faces；本地方案可使用 compare_with_extractor，云服务按实际 API 返回独立分数。
4. 外部调用超时、重试、费用上限和新增依赖／配置由框架同学统一配置。本次未增加任何依赖或公共配置，也没有自行安装人脸模型或发送照片。
5. 用授权样本标定 FACE_SIM_THRESHOLD，再做独立真实验收。原图模糊、无脸、多脸，以及候选提取失败的处理需与框架统一；当前适配层明确报错，尚未提供逐候选容错策略。

真实视觉和返工使用已有 LLM_API_KEY、LLM_MODEL_VISION、LLM_MODEL_AGENT、LLM_BASE_URL 等配置。开启前确认服务获准处理这些照片。代码不会向模型发送 brief.invitation 的姓名、日期、地点等交付资料；任务、图片内容和原始错误不写日志。错误消息使用用户可读中文。

## 离线人工与模型结果对照

```bash
uv run python -m app.modules.review.evaluation /私有目录/annotations.json /私有目录/predictions.json
```

annotations.json 是人工标注模板填好后的**列表**。身份标签使用“像本人”“不像本人”“无法判断”；review.status 使用 pending（未复核）、reviewed（已复核）、adjudicated（分歧已裁定）。human_passed 只能为 true、false 或 null；仅已复核／裁定且非 null 的标签计入指标。

模板的 expected_round_target 是整轮人工裁定的返工方向，null 表示未裁定；候选内 expected_target 用于人工逐图讨论，不能把同一个整轮返工决策重复算四遍。

predictions.json 是离线报告列表，每项示例：

```json
[
  {
    "sample_id": "sample_001",
    "result": {
      "scores": [{"image_id": "img_1", "face_sim": [0.9, 0.88], "body_ok": true, "hands_ok": true, "issues": [], "total": 0.89}],
      "best_image_id": "img_1",
      "passed": true
    },
    "retouch_plan": {"target": "none", "patch": "选择已合格候选", "image_id": "img_1"}
  }
]
```

sample_id、result 包装是离线报告格式，不新增工单字段。图片以 sample_id + image_id 对齐。工具依据 scores 和当前 FACE_SIM_THRESHOLD 重新判定单图是否通过，不以整轮 passed 代替每张图结果；重新计算后的阈值应在报告运行记录中登记。

输出包含 tp/tn/fp/fn（正类为“合格”）、有效图片数、未复核／无法判断数、缺预测数，以及误放行率、误拦截率和整轮路由一致率的分子、分母、比率。没有分母时为 null。缺模型预测不会伪装成“系统拒绝”。现已补充按缺陷类别的漏检率、推荐质量、耗时与调用数摘要和版本元数据，另提供阈值扫描与人物隔离检查；具体命令与统计限制见 [完善进度与运行指南](完善进度与运行指南.md)。

空模板、真实照片、原始授权与真实报告不用于本次提交。`batch_eval.py` 仍是 fake 示例工单批量工具，不能接收人工标注模板。
