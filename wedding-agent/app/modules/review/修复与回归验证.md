# review 检查问题修复与回归验证

分支 module/review，仅修改本模块目录；没有修改公共骨架、契约、依赖和配置，尚未提交。

## 已复现问题与修复

### 自动返工方向

原行为：没有用户反馈，一位人脸相似度不足，agent 仍可返回 look（换婚纱）并被接受。

现行为：quality.py 确定 required_target_without_feedback；有合格候选时必须 none，全部不合格时按最高总分候选的缺陷确定方向，脸／手／人数优先 generate，比例及镜头问题 shot，造型 look，其他指令问题 prompt。agent 负责具体 patch 和合格候选选择，不能绕过方向约束。用户明确重做仍优先按现有 reason 路由。

qualified_ids 也重新与评分核对，不能传入伪造合格列表。输入状态、节点名称和返回字段均保持原契约。

### 标定与验收版本

原行为：标定集和验收集使用不同人脸模型，仍返回阈值建议。

现行为：两个集合共同校验 mode、face_model、score_scale、vision_model、prompt_version；字段必须是非空字符串，缺失或跨集合不一致都会报 FILE_INVALID。还拒绝额外样本和未登记候选，避免它们影响扫描。

dataset_version 可用于运行登记。新旧基线对比要求同一 dataset_version、完整且相同的 sample_id/image_id 覆盖、相同模式和分数尺度；两次运行的模型或提示词版本可以不同，这正是对比的对象。对比必须记录两边各自的 face_sim_threshold。

## 共用规则与报告

quality.py 提供分数校验、阈值校验、合格判定、缺陷识别和自动返工方向。node、real、evaluation 共用规则；calibration 通过 evaluation 复用，避免复制门槛逻辑。缺陷关键词仍是内部规则，无法替代实际效果验收。

报告新增：

- identity_a、identity_b 独立漏检率，避免 A 没检出却因 B 被拒而掩盖问题；原有 identity 指标仍表示整图任一身份缺陷。
- false_accepts、false_rejects、missing_predictions、pending、route_mismatches、missing_round_routes 的匿名案例编号。
- unexpected_predictions 列出模型报告中未登记的样本／候选。
- missing_run_metadata 明确有多少记录缺少必要运行信息；普通 evaluation 可报告不完整元数据，calibration 与 regression 则拒绝用它作标定／对比。

新工具 regression 输出新旧指标、current-minus-baseline 比率差、判定变化案例。误放行、误拦截和漏检率的差值为正表示变差；推荐质量、路由一致率为正表示改善。没有分母的差值保持 null，无已复核标签时 status=insufficient_labels，不能声称比较成功。

## 稳定性验证

- 无用户反馈时，脸、手、比例、风格、主体人数的问题不能被错误 agent 方向绕过。
- 模型同时声称某维度通过、又报告该维度缺陷时明确报错，不放行。
- 非法／非有限人脸阈值、调用步骤、超时或 SDK 重试配置在模型调用前被拦截。
- 两个并行真实返工调用不串用户意见，输入不被修改。
- 两个并行六接口任务不串照片、候选或交付。
- 连续两次重做后第三次被框架 REDO_LIMIT 拒绝，已有预览仍可确认并交付。
- 历史候选、漏返候选和连续质检失败的已有测试继续通过。

## 运行与演示

在 wedding-agent/ 执行：

```bash
uv run pytest app/modules/review
uv run pytest tests/test_contracts.py
uv run pytest
uv run python -m app.modules.review.smoke --mode mock
uv run python -m app.modules.review.calibration app/modules/review/examples/synthetic_annotations.json app/modules/review/examples/synthetic_predictions.json --thresholds 0.5 0.7 0.9
uv run python -m app.modules.review.regression app/modules/review/examples/synthetic_annotations.json app/modules/review/examples/synthetic_predictions.json app/modules/review/examples/synthetic_predictions_v2.json
```

合成基线对比演示结果：误放行率差 -1.0、误拦截率差 +0.5，8 张候选的判定变化。它说明改善一个指标可能损害另一个指标，不能自动认定新版更好。全部是程序构造的标签和分数，不是项目真实效果。

实际测试：review 197 项、契约 24 项、全量 267 项全部通过；上述 mock、标定、基线对比命令已执行。真实服务、人脸供应商和授权真人照片未使用。

还需外部输入：人脸服务及公共配置、获准模型与预算、授权真实回归集、单张候选无法评测时的统一处理政策。这些没有用测试替身冒充完成。
