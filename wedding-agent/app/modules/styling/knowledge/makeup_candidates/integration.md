# 妆容候选数据接入交接

## 本 PR 已完成

56张原图对应的56份单例数据、14个分类路由、2个主入口，含可见特征、单例风格假设、确认后固定边界、可变量、来源局限及未执行的提示词草稿。图片服务地址均为 null，未接通检索运行时，未生图。婚纱 PR #14 独立维护，不要求先合并婚纱数据。

## 框架师接下来做什么

1. 审查并合并本数据 PR。原图片和本地审阅页在牵头人另交的 `妆容01候选底库_图片与Skill交接包_20261016.zip`；校验包哈希见 `image_service_manifest.json`。仓库不包含 `review-images/`，不能将其当作部署静态目录。
2. 将包内56个文件按图片编号上传现有图片服务。`package_file` 相对外部解压根目录；`assets_file`、`recipe_file`、`catalog_file` 相对本目录。保留原文件和透明通道，原样存储时按 manifest 校验 SHA256；服务转码应保留原图并另记派生版本。两条 AI 标识图可归档存储，但不进入默认真人候选。
3. 在 manifest 和每例 `assets.json` 同步回填 `service_url`，或填对象编号及访问方式并由后端动态解析。飞书 `cloud_file` 是预览页，不是图像直链；临时签名不当永久地址，凭据放服务配置，不写入本目录。
4. 由妆造师/资产库负责人接入检索。先按新娘/新郎与分类选择，再按 case_id 读取 recipe，需要参考图时读取 assets；参考用途为 `makeup`，不作客户身份参考。`image_service_manifest.json` 提供建议物料编号 `makeup_fmakeup000040` 等，仍保留原 case_id 双向映射。01–07 是各妆容库自己的分类编号，不能直接写入工单 `brief.style`。
5. **现有 search_assets 不会因合并这些 JSON 自动工作。** 当前 `app/modules/assets/node.py::search_assets` 读取 `templates/catalog.json` 的 `file` 字段，并检查本地模板文件存在后返回 URL，不读取本目录 `service_url`。框架/资产库负责人须选择导入受控本地模板，或实现现有图片服务的适配；本 PR 不代改该模块。其标签匹配目前是任一标签命中，不能靠同时传“新娘+分类”就假设交集过滤，适配器需要明确过滤 audience/category 和状态。
6. 现有造型输出继续遵守 `look = {text, style, references}` 契约；不要把 recipe 整包或新字段直接塞进工单。用户确认后的妆效进入 look 的文字，参考图沿用现有 reference 契约。`prompt_recipe` 只是数据表达草案，不是 `prompts/` 下已接通的模板，也不证明还原了原始提示词。
7. **只做只读联调**：先用 FMAKEUP000040、MMAKEUP000036 验证“选编号→读取特征和变量→显示同编号图片”，再检查其余映射。由实际部署后端读取图片，确认返回可解码图像而非登录页，并验证前端显示。记录 backend_read_verified、ui_preview_verified；接入完成后 catalog.image_service_status 可改为 bound_for_read_only_pilot。不要自动升级来源或 production_ready。
8. 回传填写好的服务映射、后端/界面验证结果和集成 PR；本轮不调用生图或训练。

## 来源及使用边界

FMAKEUP000036、FMAKEUP000043：源索引记载 AI/即梦标识，默认排除；不能因旧清洗已去掉标识而认定为真人。其余54例 `source_truth_status=unverified`，未知不等于 AI，也不等于认证实拍。来源索引中的旧“已入库”等用语不覆盖当前状态。用户确认提取逻辑不等于真实性验证。

`observed` 仅是图片中可见现象，可能同时受光线、后期影响；`inferred` 是单例解释；`proposed` 是适配建议，未经生成评测。不能编造产品、色号、真实化妆步骤或把样片人物的肤色、五官、虹膜、发型锁定给客户。固定的是客户确认后本套方案的一致性；妆造师最新明确方案优先于库内默认，客户明确要求有冲突时协调。

## 验收

- 56个编号一一对应，不丢失旧两例；默认审阅检索为54条，AI标识两条不能意外混入。
- 来源状态在选择界面或审阅详情中可见，未核验不自动变为真人。
- 原图可从部署服务读取，前端显示正确方向、比例与透明背景，不卡浏览器飞书登录态。
- 没有改婚纱数据、工单字段或生成流程；没有因合并文件触发生图。
