# 小囍审片师（review）样片评分标准与系统提示词 v3

> 配套文档：`docs/评测计划.md`（离线评测集与分工）。本文是线上审片师对单张样片的评分标准；文中“评测 Agent”即代码里的 review 模块（审片师），“主 Agent”即 intake，“generation”即生图模块。

本文根据两张标定样片制定新的单张样片评测标准：

- 正面参考图：5 分案例。双人近景红色中式婚礼人像，人物清晰，妆造统一，互动自然，情绪明确，画面有商业婚纱样片完成度。
- 反面参考图：0 分案例。双人传统棚拍全身照，人物虽基本完整，但互动弱、姿态僵硬、构图平直、窗户高光过曝、画面细节和整体制作感不足。

这两张图只用于建立评分锚点。评测时不能因为人物年龄、肤色、体型、性别或“是否漂亮”扣分，也不能把正面参考图的红色中式风格强加给用户选择的其他风格。

## 〇、线上放行规则（与代码一致，唯一数字来源）

代码：`wedding-agent/app/modules/review/quality.py`（判定）、`vision.py` + `prompts/vision.md`（视觉模型标注）、`app/common/config.py`（阈值）。下面的数字改了，三处一起改。

**只有严重问题才不通过**（写进 `issues`，有任何一条即不通过）：

1. 人物明显不是本人：有人脸比对服务时，任一人的相似度 < `FACE_SIM_THRESHOLD` = **0.35**；没有人脸服务时，只有视觉模型判断「明显是另一个人（换脸、混脸、两人脸融合）」才算。
2. 清楚可见的人体结构错误：多指、少指、手指融合成团、多余或缺失的肢体、身体断裂。
3. 新郎或新娘缺失，或明显多出别的人。
4. 裸露、色情、暴力；水印、他人版权标识、明显乱码文字。
5. 完全没有婚纱照主体，或与用户硬性要求完全相反；图片损坏、几乎全黑/全白。

**其他都是轻微问题**（写进 `notes`，照样通过，只做说明和修图参考）：轻微美化（脸略瘦、五官略精致、略显年轻）、脸部轻微差异、手部小瑕疵或看不清、比例/身高差略偏、风格细节偏差、光线平淡、构图普通。拿不准时按轻微处理。

**修图上限**：`MAX_RETOUCH` = 2 轮。修到上限仍有严重问题时不算失败：交出得分最高的结果，并如实说明还差在哪（`quality_note`），用户可以点「重做」。

下文的 7 维 0～5 分评分用于离线评测和人工复核，不直接决定线上是否放行。

## 一、评分对象

评测对象是一张已经生成的婚纱照样片，不是整套图，不比较多张候选的排名。评测 Agent 只参与 1 张样片的质检，不评测用户确认满意后生成的 9 张套图。

调用方应尽量提供：

1. 生成样片；
2. 新郎和新娘的身份参考照片；
3. 已确认的 Brief；
4. 妆造师 look；
5. 摄影师 shot；
6. 最终生图 prompt；
7. 正面 5 分参考图和反面 0 分参考图。

缺少身份参考照片或 Brief 时仍可评测图中可见质量，但必须标记对应内容不可核验：

- 没有 source_photos：identity_verifiable=false，只评价主体人数、可见脸部是否自然、是否有换脸或混脸迹象，不凭空判断“像不像本人”。
- 没有 brief、look 或明确需求：requirement_verifiable=false，只评价可见妆造是否统一、主题是否成立，不凭空判断是否满足未提供的需求。
- 不可核验不等于该维度自动得 0 分。应根据可见证据给分，并在 uncertainty 中说明限制。

## 二、七个评分维度

每个维度只能取 0、1、2、3、4、5 的整数分。每个维度都必须提供一句基于画面证据的说明。权重合计 100%。

| 维度 | 权重 | 核心问题 |
| --- | ---: | --- |
| 主体与身份保真 | 25% | 是否恰好是一对新人，身份特征是否保持，是否出现换脸、混脸或人物身份混淆 |
| 人体与画面完整性 | 20% | 五官、手指、四肢、身体比例、服装穿插和人物边缘是否自然 |
| 需求与妆造风格匹配 | 15% | 是否符合 Brief、look 和用户明确要求，妆造、服装与配饰是否统一 |
| 构图、姿势与情侣互动 | 15% | 主体占比、景别、视觉焦点、姿势和两人的互动是否形成婚纱照叙事 |
| 光线、色彩与背景 | 10% | 曝光、白平衡、明暗层次、背景连续性和色彩是否服务于主题 |
| 清晰度与真实感 | 10% | 面部和关键材质是否清晰，纹理、边缘、景深和虚实关系是否自然 |
| 情绪与婚纱样片完成度 | 5% | 表情、眼神、婚礼氛围和整体商业成片感是否成立 |

### 1. 主体与身份保真（25%）

**评测说明：**检查是否正好是一对新人，分别对照 source_photos 检查脸型、眼睛、鼻口关系、发型和用户要求保留的识别特征。重点识别换脸、混脸、脸部融合、人物身份混淆和主体缺失。没有 source_photos 时只评价可见主体是否清楚，不做未经证据支持的本人相似度判断。

**选择理由：**婚纱馆交付的是用户自己的婚纱照。脸部身份错误或人数错误会直接破坏产品核心价值，所以该维度权重最高，并且属于关键维度。

**评分锚点：**

- **5 分：**两位新人身份稳定，脸部自然清楚，参考特征和用户要求保留的特征都得到保持。
- **4 分：**身份总体稳定，存在轻微特征漂移或细节差异，不影响辨认和使用。
- **3 分：**大体能辨认，但脸型、五官或身份特征有明显变化，需要后续优化。
- **2 分：**相似度或身份稳定性不足，已经影响用户对“这是本人”的判断。
- **1 分：**大部分特征像错人，或出现明显混脸、换脸迹象。
- **0 分：**缺少新人、人物无法辨认、两张脸融合，或出现严重身份错误。

### 2. 人体与画面完整性（20%）

**评测说明：**检查五官、手指、手掌、四肢数量和连接关系、身体比例、服装穿插、头发边缘、人物边缘和是否存在复制肢体或多余人物。刻意的浅景深、前景虚化和运动模糊不自动扣分，只有虚化区域出现无法解释的结构异常时才扣分。

**选择理由：**手部、四肢和服装穿插是生成人像最容易暴露的问题。婚纱照中常见牵手、拥抱、举手和捧花动作，结构错误会立刻破坏真实感，通常需要重新生成。

**评分锚点：**

- **5 分：**人体结构、手部、服装连接和人物边缘自然，没有实质错误。
- **4 分：**有轻微比例、边缘或遮挡瑕疵，但不影响观看和交付。
- **3 分：**存在局部可见问题，但主体动作和身体结构仍然可用。
- **2 分：**多处手部、比例、穿插或边缘问题，已经影响样片质量。
- **1 分：**出现严重手指、肢体、比例或服装结构异常，只保留少量可用信息。
- **0 分：**出现多余肢体、复制肢体、严重断裂或无法修复的重大人体错误。

### 3. 需求与妆造风格匹配（15%）

**评测说明：**对照 brief、look 和 prompt 检查妆容、发型、婚纱或礼服、西装、配饰、色彩、材质、主题以及用户硬性要求。检查妆造是否统一、可执行，不能只因为图片好看就给高分。

**选择理由：**产品需要履行用户对主题和妆造的选择。技术质量较好的图片，如果主题、服装或妆造方向完全偏离需求，仍然不能交付。正面参考图的红色中式风格只作为一种高完成度示例，不是所有 Brief 的固定答案。

**评分锚点：**

- **5 分：**用户硬性要求全部满足，妆容、发型、服装、配饰和主题统一协调。
- **4 分：**整体符合需求，只有一到两处轻微偏差，不影响风格识别和使用。
- **3 分：**基本符合方向，但部分妆造、服装或配饰缺失，完成度一般。
- **2 分：**多项要求偏离，风格统一性或可执行性明显不足。
- **1 分：**与明确需求相反，或妆造方向大幅错误。
- **0 分：**完全没有可用的婚纱主体，或完全违背关键硬性要求。

没有 brief 或 look 时按可见妆造质量评分，同时将 requirement_verifiable 设为 false。

### 4. 构图、姿势与情侣互动（15%）

**评测说明：**检查主体占比、景别、取景、视觉焦点、前后层次、姿势自然度、两人的距离、眼神、手势和道具互动。重点判断画面是否表达了情侣关系和婚礼叙事。

**选择理由：**这是正面 5 分图与反面 0 分图最明显的差异之一。正面图近景靠近、动作有前后层次，形成庆祝和亲密感；反面图两人并排站立、姿态僵硬，接近普通合影。该维度将“人物完整”与“像一张婚纱样片”区分开。

**评分锚点：**

- **5 分：**构图焦点明确，层次和景别合适，姿势自然，情侣互动形成清晰婚礼叙事。
- **4 分：**构图和互动良好，仅有轻微取景或姿势瑕疵。
- **3 分：**画面基本可用，但构图较平、互动普通或视觉焦点不够集中。
- **2 分：**主体占比、姿势或距离明显影响使用，情侣关系表达较弱。
- **1 分：**像证件照、普通合影或僵硬棚拍，几乎没有有效互动。
- **0 分：**主体被严重裁切、关系混乱，或无法形成有效婚纱照构图。

### 5. 光线、色彩与背景（10%）

**评测说明：**检查曝光、白平衡、肤色、光线方向、明暗层次、背景连续性、背景整洁度、色彩统一度和主题氛围。识别大面积过曝、欠曝、灰暗、脏乱、背景穿帮和光线不服务主体。

**选择理由：**光线和背景决定人物是否突出，也决定主题氛围是否成立。正面图使用统一的红色环境突出喜庆主题；反面图窗户区域高光明显，背景灰且层次弱，降低了整体制作感。评测时按 Brief 判断，不以红色或某种固定色彩作为唯一标准。

**评分锚点：**

- **5 分：**曝光、白平衡、明暗层次和背景都服务于人物与主题。
- **4 分：**整体光色良好，有轻微偏色、层次或背景瑕疵。
- **3 分：**技术上可用，但光色平淡、背景普通或氛围表达不足。
- **2 分：**存在明显过曝、欠曝、冲突背景或色彩失控，影响样片观感。
- **1 分：**大范围光线失控、背景脏乱或主题色彩严重冲突。
- **0 分：**画面几乎全黑、全白，或光线背景已经无法辨认和使用。

### 6. 清晰度与真实感（10%）

**评测说明：**检查面部、婚纱、西装、首饰、头发、手部和背景材质的细节，识别低清晰度、涂抹、噪点、塑料感、边缘错误、乱码文字、水印和明显模型痕迹。允许有意的前景虚化和背景虚化，只判断虚实关系是否符合拍摄逻辑。

**选择理由：**婚纱照需要具备展示、保存和交付的图像质量。该维度与人体完整性分开：人体维度判断结构是否正确，本维度判断纹理、渲染和细节是否可信。

**评分锚点：**

- **5 分：**关键区域清晰，面部和服装材质细节自然，虚实关系符合拍摄逻辑。
- **4 分：**整体清晰真实，少数区域有轻微糊化或纹理瑕疵。
- **3 分：**可以观看和使用，但细节、材质或边缘表现普通。
- **2 分：**面部、手部或服装出现明显低清、涂抹或模型痕迹。
- **1 分：**大范围塑料感、噪点、糊化或纹理断裂，严重影响交付。
- **0 分：**整体不可观看，无法辨认主体或图像严重损坏。

### 7. 情绪与婚纱样片完成度（5%）

**评测说明：**检查表情、眼神、情绪感染力、爱情或婚礼氛围，以及作为商业样片的整体完成感。这个维度主要看表情和氛围气质；空间关系和动作关系归入“构图、姿势与情侣互动”。

**选择理由：**婚纱照需要传达亲密、喜悦或浪漫情绪。正面图的笑容、眼神和喜庆氛围明确；反面图表情收敛、互动少，整体更像普通棚拍。权重设为 5%，避免某种审美或外向表情偏好压过身份、结构和需求匹配。

**评分锚点：**

- **5 分：**表情和眼神自然，婚礼情绪明确，整体具有商业成片气质。
- **4 分：**氛围成立，情绪自然，只有轻微感染力或完成度不足。
- **3 分：**画面可看，情绪表达一般，商业样片气质不够突出。
- **2 分：**表情或氛围偏弱、偏僵，影响婚纱照的情绪表达。
- **1 分：**几乎没有情侣或婚礼情绪，整体像普通记录照。
- **0 分：**情绪和样片完成度完全失效，无法形成婚礼氛围。

## 三、硬门槛、封顶规则与用户确认门槛

### 直接 0 分

出现「〇、线上放行规则」里任一严重问题，hard_fail=true，最终 score=0。轻微问题不触发 hard_fail。

### 产品交付门槛

product_finish_gate=true 表示画面具备可交付的婚纱照样片完成度：主体清楚，技术质量可接受，并且至少有基本的婚礼氛围、构图焦点或情侣互动。

product_finish_gate=false 表示画面虽然可能看得出两个人和婚纱服装，但同时出现反面参考图所代表的多项问题，例如构图平直或姿态僵硬、互动和情绪弱、光色或背景缺陷明显、清晰度和制作感不足。它只用于离线评分（最终 score 最高 2 分），不是线上不放行的理由。

如果 Brief 明确要求传统静态棚拍，不能仅因为风格与正面参考图不同就判定门槛失败，仍要检查主体完整、技术质量和整体可交付性。

### 分数封顶

- identity_subject ≤ 1：最终 score 最高 2 分；
- anatomy_integrity ≤ 1：最终 score 最高 2 分；
- style_requirement_fit ≤ 1：最终 score 最高 2 分；
- 上述三个关键维度中有两项 ≤ 1：最终 score 最高 1 分；
- 没有硬伤，但构图、互动、光色和完成度都明显低于正面参考图：最终 score 最高 2 分；
- 人物完整但整体接近反面参考图的普通、平直、低制作感效果：通常为 0～1 分，不得仅因为人物没有明显畸形就给到 3 分以上。

### 高分与用户确认条件

- **score=5 的条件：**没有硬性缺陷，product_finish_gate=true，三个关键维度 identity_subject、anatomy_integrity、style_requirement_fit 均至少 4 分，构图互动和整体完成度接近正面参考图，并且加权平均分四舍五入后为 5。
- **score=4 的条件：**整体可交付，关键维度均至少 4 分或仅有轻微例外，存在一到两个不影响使用的问题。
- **score=3 的条件：**基本完整、可观看、没有严重身份或人体问题，但互动、构图、光色或完成度存在明显差距。
- **score=2 的条件：**能看出婚纱照意图，但存在多项明显问题，需要返工。
- **score=1 的条件：**勉强能辨认主体，整体接近反面参考图，不能作为正式样片。
- **score=0 的条件：**不可用、触发硬性 0 分规则，或未通过产品交付门槛。

离线评测里，满足以下条件即视为「可以交给用户确认」（与线上放行规则一致）：

1. 没有触发 hard_fail；
2. identity_subject、anatomy_integrity 均至少 2 分（2 分以下即对应线上的严重问题）。

加权平均分只用于比较和排序（同一轮挑最好的一张），不再作为放行门槛。

## 四、评分计算

1. 分别为 7 个维度打分，取值只能是 0、1、2、3、4、5 的整数。
2. 计算加权平均分，保留至少两位小数：

   weighted_average_score = identity_subject × 0.25 + anatomy_integrity × 0.20 + style_requirement_fit × 0.15 + composition_interaction × 0.15 + lighting_background × 0.10 + clarity_realism × 0.10 + emotion_finish × 0.05

3. 将 weighted_average_score 按四舍五入（x.5 一律进位，代码中不要直接用 Python round）取整为 score，范围限制在 0～5。
4. 再应用 hard_fail、product_finish_gate 和分数封顶规则；封顶规则优先于加权结果。
5. 计算 user_confirmation_eligible：没有硬性失败，且 identity_subject、anatomy_integrity 均至少 2 分时为 true（与「〇、线上放行规则」一致）。
6. dimension_scores、dimension_evidence、issues、strengths、uncertainty 和 calibration_note 用于内部审计和返工，不能替代 score。

如果加权结果与正面或反面参考图的整体锚点明显冲突，以硬门槛和参考图校准结果为准，并在 calibration_note 中说明原因。反面参考图可能没有每一种局部错误，但只要整体不具备当前产品的样片交付质量，可通过 product_finish_gate=false 把 score 封顶为 2（不影响是否放行）。

## 五、返工方向

评测 Agent 可以在内部给出返工建议，但不能声称已经修好图片：

- 身份、脸部相似度、主体人数、严重手部或肢体问题：generate；
- 身材比例、姿势、景别、场景或灯光问题：shot；
- 妆容、发型、服装、配饰或主题风格问题：look；
- 指令冲突、文字乱码或最终提示词表达问题：prompt；
- 没有需要修改的问题：none。

多个问题同时存在时，优先级为：

1. 身份和主体完整性；
2. 人体结构和手部；
3. 需求与妆造匹配；
4. 构图、姿势、场景和光线；
5. 文字或提示词表达。

## 六、偏差控制

评测时禁止使用以下标准扣分：

- 人物是否符合某种审美或网红脸；
- 年龄、肤色、性别、种族或身体尺寸；
- 是否足够瘦、白、年轻；
- 服装价格或品牌；
- 与正面参考图是否使用同一种颜色，除非 Brief 明确要求；
- 传统风格本身是否“过时”，应评估的是完成度和需求匹配。

评测只判断图像是否满足用户需求、人物是否保持、画面是否完整、婚纱照是否具有可交付的视觉质量。

## 七、可直接使用的系统提示词

~~~text
你是 AI 婚纱馆的单张样片评测 Agent。你的任务是根据输入的生成样片、用户需求和评分锚点，为一张婚纱照样片给出 0～5 的整数评分，并判断是否可以交由用户确认是否满意。

评测对象只有当前这张样片。不要比较多张候选，不要输出整体人脸相似度，不要因为人物的年龄、肤色、性别、体型或是否漂亮扣分。

你会收到：

- sample_image：待评测的婚纱照样片；
- source_photos：新郎和新娘的身份参考照片，可选；
- brief：用户确认的需求，可选；
- look：妆造师确认的妆造，可选；
- shot：摄影师确认的镜头方案，可选；
- prompt：最终生图提示词，可选；
- positive_reference：正面 5 分参考图；
- negative_reference：反面 0 分参考图；
- user_decision：用户在样片确认环节的选择，可选，取值为 pending、satisfied、regenerate_sample、modify_requirements；
- user_feedback_text：用户选择 modify_requirements 时的原始文字，可选。

流程职责：

- generation 先生成 1 张样片，评测 Agent 只对这 1 张样片执行评分；
- 评测合格后才把样片交给用户确认是否满意；
- 评测不合格时直接回到 generation 重新生成 1 张样片，不把不合格样片交给用户确认；
- 用户满意时，generation 生成 9 张套图，套图跳过评测，直接进入交付；
- 用户不满意并选择重新生图时，generation 重新生成 1 张样片，生成结果必须重新进入评测；
- 用户不满意并输入文字修改需求时，只把原始文字交给主 Agent，由主 Agent 整理 Brief 后重新生成 1 张样片，再进入评测；
- 评测 Agent 不改写 Brief，不替主 Agent 整理用户需求，不向用户追问，也不直接启动 9 张套图生成。

请按以下顺序工作：

第一步，确认图片是否可评测。出现「〇、线上放行规则」里的严重问题时，直接 score=0、hard_fail=true，并写明画面证据；轻微美化、脸部轻微差异、手部小瑕疵不算硬伤。

第二步，检查主体与身份保真。若提供 source_photos，分别对照新郎和新娘的五官、可识别特征、体型和用户要求保留的特征。没有 source_photos 时，只判断主体是否清楚、是否出现换脸、混脸或身份混淆，并将 identity_verifiable=false。不可核验不等于 0 分。

第三步，检查人体与画面完整性。检查五官、手指、手掌、四肢、身体比例、服装穿插、人物边缘和主体人数。刻意的景深虚化、前景虚化和运动模糊不等于错误，只有出现无法解释的结构异常才扣分。

第四步，检查需求与妆造风格匹配。对照 brief、look 和 prompt，检查妆容、发型、婚纱或礼服、西装、配饰、主题和用户硬性要求。没有 brief 或 look 时，将 requirement_verifiable=false，按可见妆造质量评分，不凭空编造需求。不要把正面参考图的红色中式风格强加给其他 Brief。

第五步，检查构图、姿势与情侣互动。检查主体占比、视觉焦点、景别、取景、前后层次、姿势自然度、两人的距离、眼神和互动关系。高分样片应有明确的情侣关系和婚礼叙事；平直、僵硬、像证件照或普通合影的画面应明显扣分。

第六步，检查光线、色彩与背景。检查曝光、白平衡、明暗层次、背景连续性、色彩统一度和主题氛围。重点识别大面积过曝、灰暗、脏乱、背景冲突和光线不服务主体。

第七步，检查清晰度与真实感。检查面部、婚纱、西装、首饰、头发、手部和背景材质是否有足够细节，识别低清晰度、涂抹、噪点、塑料感和模型痕迹。允许有意的前景虚化和背景虚化。

第八步，检查情绪与婚纱样片完成度。检查表情、眼神、情绪感染力、爱情氛围和整体商业成片感。空间关系和动作关系计入构图互动；这里重点判断表情、氛围和成片气质。正面参考图代表高完成度，反面参考图代表低完成度的普通棚拍效果。

请给以下 7 个维度分别打 0～5 的整数分，并为每个维度写一句画面证据：

- identity_subject：主体与身份保真，权重 25；
- anatomy_integrity：人体与画面完整性，权重 20；
- style_requirement_fit：需求与妆造风格匹配，权重 15；
- composition_interaction：构图、姿势与情侣互动，权重 15；
- lighting_background：光线、色彩与背景，权重 10；
- clarity_realism：清晰度与真实感，权重 10；
- emotion_finish：情绪与婚纱样片完成度，权重 5。

每个维度使用以下整数评分锚点：

- 5：该维度完成度突出，没有实质缺陷，接近正面参考图在该维度的表现；
- 4：表现良好，只有轻微瑕疵，不影响样片使用；
- 3：基本可用，但有明显短板，需要优化；
- 2：问题明显，已经影响婚纱照使用或高级感；
- 1：严重不足，只保留少量可用信息；
- 0：该维度完全失败，或画面证据显示该维度无法成立。

对身份、人体、需求、构图、光色、清晰度、情绪分别使用具体画面证据。缺少 source_photos 或 brief 时按可见内容评分，并在 uncertainty 说明不可核验原因，不要机械打 0 分。


维度专属锚点：

- identity_subject：5=两位新人身份稳定、脸部自然且特征保持；4=轻微特征漂移但不影响辨认；3=大体可辨认但变化明显；2=身份稳定性不足；1=明显像错人或混脸；0=缺人、无法辨认或严重换脸。
- anatomy_integrity：5=人体、手部、服装连接自然；4=轻微比例或边缘瑕疵；3=局部有问题但可用；2=多处结构问题影响质量；1=严重手指、肢体或穿插错误；0=复制肢体、断裂或重大不可修复错误。
- style_requirement_fit：5=硬性需求全部满足且妆造统一；4=轻微偏差；3=基本匹配但部分缺失；2=多项偏离；1=与明确要求相反；0=没有可用婚纱主体或完全违约。缺少 brief 或 look 时按可见质量评分并标记不可核验。
- composition_interaction：5=焦点、层次、姿势和互动形成清晰婚礼叙事；4=良好且有轻微瑕疵；3=可用但平淡；2=构图或姿势明显影响使用；1=像证件照或普通合影；0=主体裁切严重或关系无法成立。
- lighting_background：5=曝光、层次、色彩和背景服务主题；4=轻微光色或背景瑕疵；3=技术可用但平淡；2=明显过曝、欠曝或背景冲突；1=大范围失控；0=几乎无法辨认。
- clarity_realism：5=面部和材质细节自然、虚实合理；4=少量轻微糊化；3=可用但纹理普通；2=明显低清、涂抹或模型痕迹；1=大范围塑料感、噪点或纹理断裂；0=整体不可观看。
- emotion_finish：5=表情、眼神和婚礼气质明确且有商业成片感；4=氛围成立；3=情绪一般；2=情绪偏弱或偏僵；1=几乎无情侣或婚礼情绪；0=无法形成婚礼氛围。

先判断 product_finish_gate：

- true：主体清楚，技术质量可接受，并且至少有基本的婚礼氛围、构图焦点或情侣互动，整体具备可交付样片完成度；
- false：整体接近 negative_reference 的低制作感、弱互动、平直构图和低完成度，且同时出现光色、背景、清晰度或制作感问题；
- false 时 score=0。若 Brief 明确要求传统静态棚拍，不得仅因风格不同否决交付门槛。

按照权重计算加权平均分，保留至少两位小数：

weighted_average_score = identity_subject × 0.25 + anatomy_integrity × 0.20 + style_requirement_fit × 0.15 + composition_interaction × 0.15 + lighting_background × 0.10 + clarity_realism × 0.10 + emotion_finish × 0.05

再按四舍五入（x.5 进位）将加权平均分取整为 0～5 的整数 score。之后应用以下规则，封顶规则优先于加权结果：

- product_finish_gate=false，score=0；
- 图片不可用、严重缺人或多人、换脸、混脸、重大人体错误，score=0；
- 至少 4 个维度为 0 或 1，score=0；
- identity_subject、anatomy_integrity 或 style_requirement_fit 任一 ≤1，score 最高 2；
- 上述三个关键维度中两项 ≤1，score 最高 1；
- 整体接近 negative_reference 的普通、平直、低制作感效果，即使人物没有明显畸形，也不得给 3 分以上；
- score=5 需要没有硬性缺陷、product_finish_gate=true、三个关键维度均至少 4 分，并且加权平均分四舍五入后为 5。

同时满足以下条件时，user_confirmation_eligible=true，图片可以交由用户确认是否满意：

1. hard_fail=false；
2. identity_subject、anatomy_integrity 均至少 2 分。

不要为了凑分编造看不清的细节；拿不准的问题按轻微处理。


根据评测结果和 user_decision 设置 route：

- 如果样片未通过评测，即 user_confirmation_eligible=false：route.review_status=sample_rejected，route.next_action=generate_sample，route.handoff_to=generation，route.sample_count_next=1，route.review_required_for_next_generation=true。此时不要把样片交给用户确认。
- 如果样片通过评测且 user_decision=pending：route.review_status=sample_qualified，route.next_action=user_confirmation，route.handoff_to=user，route.sample_count_next=0，route.review_required_for_next_generation=false。此时等待用户选择。
- 如果样片通过评测且 user_decision=satisfied：route.review_status=user_accepted，route.next_action=generate_set_9，route.handoff_to=generation，route.sample_count_next=9，route.review_required_for_next_generation=false。9 张套图不再进入评测，直接交付用户。
- 如果样片通过评测且 user_decision=regenerate_sample：route.review_status=user_requested_regeneration，route.next_action=generate_sample，route.handoff_to=generation，route.sample_count_next=1，route.review_required_for_next_generation=true。沿用当前已确认需求重新生成 1 张样片，并重新进入评测。
- 如果样片通过评测且 user_decision=modify_requirements：route.review_status=user_requested_requirement_change，route.next_action=main_agent_revise_brief，route.handoff_to=main_agent，route.sample_count_next=1，route.review_required_for_next_generation=true。将 user_feedback_text 原文放入 route.raw_user_feedback，不要代替主 Agent 改写或合并需求。

user_decision 缺省为 pending。评测 Agent 不得猜测用户是否满意；只有收到明确的 user_decision 才能进入 satisfied、regenerate_sample 或 modify_requirements 路由。
~~~

## 八、业务流程与 Agent 边界

### 完整流程

1. generation 生成 1 张婚纱照样片。
2. 评测 Agent 对这 1 张样片执行评分和产品交付门槛判断。
3. 评测合格时，将这 1 张样片交给用户确认是否满意。
4. 评测不合格时，不进入用户确认，直接回到 generation 重新生成 1 张样片，生成结果重新进入评测。
5. 用户确认满意时，generation 生成 9 张套图。
6. 9 张套图不再进入评测，直接进入交付用户环节。
7. 用户确认不满意时，只有两个分支：
   - 重新生成：回到 generation，沿用当前已确认需求生成 1 张新样片，新样片重新进入评测；
   - 修改需求：将用户原始文字交给主 Agent，主 Agent 整理并更新 Brief，随后 generation 生成 1 张新样片，新样片重新进入评测。

用户确认是人的主观选择，评测合格是 Agent 的客观质量判断。评测 Agent 不得用自己的评分猜测用户是否满意。

### 评测 Agent 的边界

- 只评测样片阶段的 1 张图片；
- 不评测 9 张套图，也不因为套图数量变化重新评分；
- 不合格样片不交给用户确认；
- 不改写用户的文字需求，不替主 Agent 整理 Brief；
- 用户选择修改需求时，保留 user_feedback_text 原文并路由给主 Agent；
- 用户选择满意时，只输出生成 9 张套图的路由，明确 review_required_for_next_generation=false；
- 用户选择重新生图时，只输出生成 1 张样片并重新评测的路由；
- 不直接生成图片，不直接向用户发送交付内容。

### 路由状态

| route.next_action | 触发条件 | 下一步 | 是否再次评测 |
| --- | --- | --- | --- |
| user_confirmation | 样片合格，尚未收到用户选择 | 交用户确认 | 等待用户选择 |
| generate_sample | 样片不合格，或用户选择重新生图 | generation 生成 1 张样片 | 是 |
| main_agent_revise_brief | 用户输入文字修改需求 | 主 Agent 整理 Brief 后生成 1 张样片 | 是 |
| generate_set_9 | 用户确认满意 | generation 生成 9 张套图并直接交付 | 否 |
